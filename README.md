# MacBook Air（M4）内置扬声器爆音排查记录

**当前情况：**macOS 升级后问题仍会出现。根据用户的实际观察，将腾讯柠檬显示的内存占用率控制在约 80% 以下，可以避免爆音；具体根因尚未确认。
**最后更新：**2026 年 9 月 30 日

## 设备配置

- 机型：MacBook Air（M4）
- 统一内存：16 GB
- 存储：512 GB
- 操作系统：macOS 27.0.1（从 27.0 升级）
- 播放输出：内置扬声器；系统信息显示输出采样率为 96 kHz
- 已安装：腾讯柠檬清理、vivo 办公套件 6.8.2

## 故障表现

随机播放时，内置扬声器偶尔会突然出现一两下噼啪声或爆音。改用耳机播放时没有复现。

## 已做排查

1. 最初参考的文章讨论的是 ToDesk 音频驱动问题；这台 Mac 上没有发现文章提到的 ToDeskOutputDriver.driver。
2. 音频 HAL 插件目录中曾有 BlackHole2ch.driver（0.5.0 版），代码签名信息显示开发者为 vivo Mobile Communication Co., Ltd.。将它移出 HAL 加载目录并重启 coreaudiod 后，音频设备列表中不再显示 BlackHole，内置扬声器仍是默认输出；但爆音之后又出现。最近检查时，BlackHole 仍不在 HAL 加载目录中。
3. 打开 vivo 办公套件时曾紧接着出现爆音；有一次退出后几秒声音恢复正常。之后在其主窗口关闭时爆音又出现，当时仍有 vivo 后台辅助进程运行，因此尚不能确认 vivo 与爆音有因果关系。
4. 关闭浏览器后，用户一度没有再听到爆音。活动监视器读数从已用内存约 14.22 GB、压缩内存约 6.83 GB、交换空间约 13.81 GB，降至约 12.58 GB、6.25 GB 和 7.47 GB。
5. 重新打开浏览器和飞书后，用户报告爆音再次出现。由于两者一起打开，无法据此区分具体是哪一个应用触发。
6. macOS 从 27.0 升级到 27.0.1 后，问题仍会出现；系统升级本身没有解决问题。
7. 用户确认约 80% 的数值来自腾讯柠檬。腾讯柠檬官方资料将其称为状态栏内存占用或内存占用率。用户观察到将此数值保持在约 80% 以下即可避免爆音。这个数值是腾讯柠檬显示的内存占用指标，不等同于 macOS 活动监视器的内存压力；其具体计算公式尚未确认。
8. 曾短时间查看系统日志，没有发现明显的 CoreAudio 错误或音频欠载信息；短时间日志检查不能排除软件或硬件问题。尚未运行 Apple Diagnostics。

## 当前判断与临时处理

目前最有效的实际办法是把腾讯柠檬显示的内存占用率维持在约 80% 以下。关闭浏览器后内存及交换空间读数下降，且重新打开浏览器和飞书后爆音曾复现，这些观察提示应用负载或内存占用可能相关；不过，它们还不能证明具体故障原因，也不能把 80% 视为所有 Mac 通用的故障阈值。

苹果将活动监视器中的内存压力显示为颜色图表，并依据可用内存、交换速率、联动内存和缓存文件等因素判断。腾讯柠檬的百分比与这一系统指标不同。

耳机播放正常而内置扬声器曾出现爆音，因此内置扬声器及其专属输出链路仍值得留意。尚无证据证明扬声器硬件损坏。

## 建议排查步骤

1. **先使用临时规避办法。**将腾讯柠檬显示值维持在已观察到的约 80% 以下；可手动关闭暂时不用的网页标签或应用。不必为了验证而故意把数值推高。
2. **爆音出现时记录系统指标。**记录腾讯柠檬百分比、当时打开的应用，并查看活动监视器“内存”页中的压力颜色和“已使用的交换”数值。不要只凭内存使用率判断系统是否处于内存压力状态。
3. **分开观察浏览器和飞书。**如果方便且已保存工作，一次只使用其中一个应用，并保持相同音频、音量和内置扬声器输出，以判断单个应用或两者同时运行是否更容易触发。
4. **如果低于约 80% 仍然爆音，可试安全模式。**关机后按住电源键，直到出现启动选项；选中启动磁盘，按住 Shift 并选择“以安全模式继续”。用相同音频测试内置扬声器。若安全模式下不再爆音，说明启动时加载的软件值得继续排查，但不能单凭这一结果锁定某个应用。
5. **如果安全模式或低负载下仍爆音，可运行 Apple Diagnostics。**断开外接设备后关机，按住电源键直到出现启动选项，再按住 Command-D。记录任何参考代码；若诊断报错或扬声器问题持续，联系 Apple 或授权服务提供商。
